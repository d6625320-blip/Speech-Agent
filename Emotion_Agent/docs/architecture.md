# 系统设计

浏览器音频 → 16 kHz 单声道预处理 → ASR 转写和独立声学情绪识别 → 状态门控 → 对话策略 → LLM 回复 → 独立 TTS → 浏览器播放。

ASR 和语音专家单轮顺序执行，以控制峰值资源。模型按需加载并在进程内复用。ASR 模型自带的情绪标签不替代自训练七分类头。

状态区分 `no_audio`、`unclear_speech`、`unknown_emotion`、`uncertain_emotion` 和 `known_emotion`。门控核验概率分布、最大分数、前两类分差和归一化熵。阈值是初始配置，不是跨域可靠性保证；分数不等于正确率。

明确的第一人称正负自述与声学候选冲突时回退到文本优先。当前只匹配少量短语，不能完整理解否定、引用或讽刺，不是独立的文本情感分类器。

策略在调用 LLM 前确定，LLM 只生成文本，不能改写结构化状态。表达指令传给支持该能力的 TTS；是否具有目标表达需要听评。

分块播放采用两阶段请求：先获取转写、策略和回复，再请求保存回复的 TTS 流。NDJSON 携带 PCM 块，浏览器连续调度；完成后保存 WAV。整段合成继续可用，原生后端不提供本接口的分块生成。

主应用一次只允许一轮 GPU 推理，不包含多人排队。专家失败保留真实转写，TTS 失败保留文字，静音及空转写返回固定澄清。历史会话只在进程内保存，受数量、轮数及 TTL 限制。

默认使用本机模型，不自动回退到云端。上传、转写和回复保存在本机输出目录，不应随源码发布。真实模型效果、首音延迟、显存和稳态 RTF 必须实测；自动测试仅验证协议与流程。详见 [评测说明](../../docs/EVALUATION.md)。
