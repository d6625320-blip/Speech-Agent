# 真人录音测试方案：66 条功能验收样本

本方案用于当前 Speech_agent / Emotion_Agent 的第一轮功能验收和问题定位，不是正式模型性能基准。所有台词为本项目编写；音频需要真人录制或按说明派生，本文及清单不包含生成或实测的录音。

## 1. 数量与执行顺序

| 组别 | 数量 | 内容 |
|---|---:|---|
| A | 42 | 七类情绪 × 每类两句话 × 三位说话人 |
| B | 6 | 相同文字不同语气、自述冲突、引用和否定 |
| C | 4 | 轻微、疲惫、模糊、前后情绪变化 |
| D | 6 | 低音量、远距离、背景噪声 |
| E | 4 | 静音、环境声、笑声、咳嗽 |
| F | 4 | 过短、约一秒、较长、超长输入 |
| 合计 | 66 | 不把原声的派生版本当成独立说话人样本 |

建议顺序：A 组 P01 → 回放确认和检查流程 → A 组 P02/P03 → B/C → D/E/F。先关闭 TTS，定位转写及情绪；再选开心、中性、悲伤、自述冲突和长语音等代表样本开启 TTS，检查语音回复。

## 2. 人员、录音和标注

1. 选择三位尽量未出现在训练数据中的说话人，编号 P01/P02/P03。同一人的编号全程固定；记录常用口音和设备即可，无需采集真实姓名。每人读下表 14 句，共 42 条。B/C/E/F 的真人部分默认由 P01 录制。
2. 典型样本先在安静环境录制，麦克风距嘴约 15–25 厘米、位置稳定。每句话单独保存，保留约 0.2–0.4 秒首尾余量，不念编号、情绪名称或录制指令。3–10 秒是建议，不必为了凑时长拖长声音。
3. 优先保存 WAV；统一成 16 kHz、单声道、PCM16 便于比较。可以先录高采样率再转换；检查播放速度和音调未改变。每条不超过 10 MiB；除 F01/F04 外遵守当前 0.35–120 秒的输入限制。
4. 先回放原声，排除削波、漏字、录到提示语等问题。不要用提高音量代替愤怒、用气声代替恐惧，或把开心全部录成笑声。不要根据模型输出反复重录直到模型答对。
5. 由 2–3 位听者独立听音频，最好先不看目标标签和台词，填写实际听感，再核对转写。`intended_emotion` 是录制要求；`human_emotion` 初始为空，须在听后填写。有分歧时注明 ambiguous/mixed，不强行归入七类。疲惫和非语言事件不是模型的新增类别。
6. `reference` 只是预填的朗读稿。录完后按实际说出的内容修订；不要把漏读、重复或数字书写格式造成的差异全部算为 ASR 错误。C04 和 E 组不参与普通七类单标签准确率。
7. 若要调整置信度门槛，使用另外的开发集；不要一边看这套验收集结果一边调门槛后仍把成绩称为独立测试结果。

## 3. A 组：七类情绪朗读稿（42 条）

表中每一行由 P01、P02、P03 各读一次。例：A01 对应 `A01_P01_happy.wav`、`A01_P02_happy.wav`、`A01_P03_happy.wav`。三个文件都放入 `Emotion_Agent/data/recording_plan66/audio/`。

| 稿件编号 | 目标表达 | 朗读内容 | 表达要求 |
|---|---|---|---|
| A01 | 开心 / happy | 太好了，这次终于做成功了，之前花的那些时间都没有白费。 | 声音轻快、有自然笑意，重音活跃；不要只提高音量或全程大笑。 |
| A02 | 开心 / happy | 刚收到消息，咱们的方案通过了，等会儿一定要好好庆祝一下。 | 声音轻快、有自然笑意，重音活跃；不要只提高音量或全程大笑。 |
| A03 | 中性 / neutral | 明天下午我们在会议室见面，我会提前把需要的材料准备好。 | 像平常交代事情，语速稳定，不刻意添加积极或消极语气。 |
| A04 | 中性 / neutral | 我把修改后的文件放在共享文件夹里了，你有空的时候可以看一下。 | 像平常交代事情，语速稳定，不刻意添加积极或消极语气。 |
| A05 | 悲伤 / sad | 我认真准备了那么久，最后还是没有通过，现在有点提不起精神。 | 有真实的失落感，语速可略慢、声音略低；不要故意低到听不清。 |
| A06 | 悲伤 / sad | 原本以为这次能一起完成，没想到最后只剩下我一个人了。 | 有真实的失落感，语速可略慢、声音略低；不要故意低到听不清。 |
| A07 | 愤怒 / angry | 这件事明明已经确认过了，为什么又临时改掉，也没有人提前告诉我？ | 带不满和质问，重音清楚、节奏略紧；不要喊叫到声音失真。 |
| A08 | 愤怒 / angry | 我已经把问题说得很清楚了，可是到现在还是没有人认真处理。 | 带不满和质问，重音清楚、节奏略紧；不要喊叫到声音失真。 |
| A09 | 恐惧 / fear | 外面突然传来那么大的声音，我现在有点不敢一个人走过去。 | 带担心、迟疑或紧张，停顿自然；不要只用气声导致无法转写。 |
| A10 | 恐惧 / fear | 这条路黑得几乎看不清，我想等有人陪我再往前走。 | 带担心、迟疑或紧张，停顿自然；不要只用气声导致无法转写。 |
| A11 | 厌恶 / disgust | 这个味道实在太难闻了，我不想再靠近，还是先把窗户打开吧。 | 表现出排斥、嫌弃、想远离的感觉，注意与单纯愤怒区分。 |
| A12 | 厌恶 / disgust | 这杯东西已经变味了，闻着就让人不舒服，先放远一点吧。 | 表现出排斥、嫌弃、想远离的感觉，注意与单纯愤怒区分。 |
| A13 | 惊讶 / surprised | 什么，结果今天就出来了？我还以为至少要再等上好几天呢。 | 像突然听到意外消息，开头有自然音高变化，然后恢复正常说话。 |
| A14 | 惊讶 / surprised | 原来那份丢了很久的文件一直就在这里，我刚才完全没有想到。 | 像突然听到意外消息，开头有自然音高变化，然后恢复正常说话。 |

A 组用来观察原始七分类结果，不要求每条都被策略层采纳。特别是 neutral 不等于 uncertain；中性是一个真实类别，不确定是系统对当前证据的判断。

## 9. 结果怎么记录与判断

每条分别记录：实际转写、人工情绪标签及分歧、专家原始类别、七类分数、最高分、前两类差距、归一化熵、筛选后类别、state/reason、回应策略、各模块耗时、trace_id，以及输入/输出音频是否能播放。原始文件、派生版本及同一说话人的记录保持可追溯。

当前默认三项筛选条件为最高分 ≥ 0.55、前两类差距 ≥ 0.12、归一化熵 ≤ 0.85，且可靠预测不能与明确自述冲突。分数默认未校准，不等于预测正确率。判定时分开看：

- 人工认为 happy、原始候选却是其他类别：检查专家泛化、录音和人工标注；不能只通过降低门槛修复分类错误。
- 原始候选 happy、筛选后为空：查看具体是哪项门槛未通过；不确定本身不等于崩溃。
- `known_emotion` 但人工听感明显不同：记录为过度自信错误，不能把通过门槛当作预测正确。
- 引用、否定被当作本人自述：检查 B05/B06。当前 `emotion/fusion.py` 为子串规则，已知可能误判，不是假定已修复的功能。
- 静音、非语言声音和预期拒绝：按各自功能要求验收，不混入典型七类准确率；非静音环境声目前可能进入 ASR，需如实记录。

分别统计原始七类效果、被采纳比例、采纳后的正确情况，避免只展示被采纳子集的准确率。A 组各说话人和各情绪都需单独查看；本套数量较少，仅适合定位问题。

## 10. 配套文件与执行命令

- `data/recording_plan66/recording_plan66.template.jsonl`：完整 66 条录音工作清单，含文件名、稿件、人工标签留空、表达要求及检查重点。
- `data/recording_plan66/evaluation_core42.template.jsonl`：A 组 42 条，可用于原有 `scripts/evaluate.py` 的 ASR、耗时和流程检查。
- `data/recording_plan66/evaluation_accepted64.template.jsonl`：除 F01/F04 外的 64 条；其中非语言/边界样本应单独人工验收，综合 CER 不作为核心识别成绩。
- `data/recording_plan66/audio/`：留给实际录音。本方案没有生成假录音，也没有填入实际识别结果。
